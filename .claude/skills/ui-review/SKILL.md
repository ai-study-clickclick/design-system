# /ui-review

만든 화면을 규칙 문서의 점검표로 확인하는 스킬이다. 점검 항목은 모두 규칙 문서의 Do's and Don'ts에 있고, 이 스킬은 점검하는 순서와 보고 방식만 정한다.

> 상태: 가안 · 태스크: 4-2. 컴포넌트(2-3)가 나오기 전이라 다른 앱 화면 캡처로 먼저 시험한다.

## 점검 대상

| 대상 | 받는 것 | 볼 수 있는 것 |
| --- | --- | --- |
| 프로토타입 | 화면 주소(`/prototypes/YYMMDD-topic`) 또는 폴더 이름 | 화면 · 코드 · 상태 장면 · 동작. 모든 항목을 점검한다. |
| 캡처 | 화면 이미지(여러 장이면 순서대로) | 화면에 보이는 것만. 코드 · 토큰 이름 · 동작 · 정확한 px 값이 필요한 항목은 "확인 불가"로 둔다. |

## 순서

1. 대상과 기준을 확인한다
   - 프로토타입: 같은 이름의 브리프(`briefs/YYMMDD-topic.md`)를 읽어 화면 성격 · 범위 · 상태 범위 · `owner`를 확인한다. 브리프가 없으면 화면 성격을 `docs/PATTERNS.md` "화면 성격"에서 골라 사람에게 확인받는다.
   - 캡처: 브리프가 없으므로 화면 성격을 `docs/PATTERNS.md` "화면 성격"에서 골라 사람에게 확인받는다. 어떤 상태의 화면인지(정상 · 기다림 · 비어 있음 · 실패 · 이용 불가)도 함께 확인한다.
2. 네 문서의 Do's and Don'ts를 읽는다: `DESIGN.md` · `docs/UX.md` · `docs/WRITING.md` · `docs/PATTERNS.md`. 판정이 애매한 항목은 그 문서 본문의 해당 장을 읽는다.
3. 화면을 본다
   - 프로토타입: 미리보기(`npm run dev` 또는 브랜치 미리보기 주소)를 기준 폭 375px로 열고, `docs/PATTERNS.md` "화면 성격별 상태 장면"에서 그 화면 성격에 필요한 장면을 하나씩 본다. 코드(`src/app/prototypes/YYMMDD-topic/`)도 읽는다.
   - 캡처: 이미지만 본다. 보이지 않는 장면은 점검하지 않는다.
4. 항목마다 판정한다

   | 판정 | 뜻 |
   | --- | --- |
   | 맞음 | 규칙대로다 |
   | 어긋남 | 규칙과 다르다 |
   | 권장 어긋남 | `[권장]` 항목과 다르다. 브리프에 다른 요청이 있으면 맞음으로 본다. |
   | 해당 없음 | 이 화면에 그 요소 · 장면이 없다 |
   | 확인 불가 | 이 대상으로는 볼 수 없다(캡처의 코드 · 동작 등) |

   - "(웹 프로토타입에서 확인 불가)" 표시가 있는 항목은 판정하지 않고 건너뛴다
   - 같은 문제가 여러 문서의 항목에 걸리면 한 줄로 묶고 문서를 함께 적는다
5. 결과를 보고한다(아래 "보고 형식")
6. 고칠지 묻는다
   - 프로토타입이고 브리프 `owner`가 현재 사용자일 때만 "어긋남"을 고칠지 묻는다. 사람이 고르거나 승인한 것만 고친다.
   - 다른 사람의 화면이나 캡처는 고치지 않는다. 고치는 방법만 보고에 적는다.
   - 고친 뒤에는 고친 항목만 다시 점검해 결과를 알린다

## 보고 형식

비개발자가 읽는다. 쉬운 말로 짧게 쓴다.

1. 한 줄 요약: 대상 · 화면 성격 · 본 장면, 어긋남 개수
2. 어긋남 표. 심한 것부터(사용자가 막히거나 잘못 누를 수 있는 것 → 규칙만 다른 것)

   | # | 문서 · 항목 | 화면에서 본 것 | 고치는 방법 |
   | --- | --- | --- | --- |

3. 권장 어긋남 표(있을 때만, 같은 열)
4. 한 줄씩: 맞음 · 해당 없음 개수, 확인 불가 항목 이름

## 하지 않는 것

- 이 파일에 점검 항목을 따로 적지 않는다. 항목은 규칙 문서의 Do's and Don'ts에만 둔다.
- 묻지 않고 고치지 않는다
- 규칙 문서 · `src/components/` · `src/styles/` · `.claude/`를 고치지 않는다(`AGENTS.md` "역할과 작업 범위"). 규칙이 잘못돼 보이면 고치지 않고 사용자에게 알린다.
- 캡처 이미지를 저장소에 올리지 않는다. 다른 회사 화면이라 공개 저장소에 둘 수 없다.
- 규칙에 없는 취향으로 어긋남을 만들지 않는다. 규칙 문서에 근거가 없는 의견은 "참고"로만 한 줄 적는다.
