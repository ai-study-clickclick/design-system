# UX.md

> 상태: 초안 v0.7 · 담당: 유진 · 태스크: 1-3
> 이 문서는 화면이 **사용하기 쉽고 이해하기 쉬운지**에 대한 규칙입니다.
> 다루는 범위: 인터랙션 · 상태 · 피드백 · 폼 · 레이아웃·반응형 · 모션 · 접근성
> 색·크기·간격·라운드·컴포넌트 모양은 `DESIGN.md`, 문구는 `WRITING.md`, 화면 유형별 구성은 `PATTERNS.md`를 따릅니다.

## 0. 읽는 법

### 0-1. 규칙 강도

| 표시 | 뜻 | Claude의 행동 |
| --- | --- | --- |
| **[필수]** | 반드시 지킴 | 지킬 수 없으면 화면을 만들기 전에 사람에게 묻는다 |
| **[권장]** | 기본으로 따름 | 브리프에 다른 요청이 있으면 그것을 따른다 |
| `[결정 필요]` | 팀 확정 전 | 함께 적힌 임시 기본값을 따른다 (15장) |

### 0-2. 다른 문서와의 경계

UX.md는 **"어떻게 동작하고, 사용자가 무엇을 겪는가"**만 정합니다. 값은 쓰지 않고 다른 문서를 가리킵니다.

| 같은 주제 | UX.md에 쓰는 것 | 다른 문서에 쓰는 것 |
| --- | --- | --- |
| 눌림 | 언제 반응하고, 어떤 상태에서 반응하지 않는지 | 눌렸을 때의 색·축소량·시간 → `DESIGN.md` |
| 레이아웃 | 가려지면 안 되는 것, 화면이 바뀔 때의 동작 | 여백·그리드·폭 값 → `DESIGN.md` |
| 모션 | 언제 쓰고 언제 끄는지 | 시간·속도 곡선 값 → `DESIGN.md` |
| 오류 | 어디에, 언제, 무엇을 담아 보여 주는지 | 오류 문장 표현 → `WRITING.md` |
| 접근성 | 누구나 쓸 수 있게 하는 동작 규칙, 어떤 글자·요소를 어느 대비 단계로 볼지 | 색 대비 기준값(APCA 방식) → `DESIGN.md` |
| 로딩 | 언제 보여 주고, 어떤 표현을 쓰는지 | 표시 지연·최소 유지 시간 → `DESIGN.md` |

**예외: 사용자 기준값.** 아래 값은 화면 모양이 아니라 **사람이 느끼고 견딜 수 있는 한계**라서 UX.md에 그대로 적습니다. `DESIGN.md`는 이 값을 넘지 않도록 정합니다.

| 값 | 위치 | 근거 |
| --- | --- | --- |
| 누르는 영역 44×44px (기본 기준), 최소 24×24px | 4-3 | 손가락으로 정확히 누를 수 있는 크기 / 공간이 부족해도 지켜야 하는 최소 크기 |
| 기다림 구간 1초·4초·10초·1분 | 5-3 | 사람이 지연을 느끼는 단계 |
| 로딩 시간 초과 10초 | 5-3 | 멈췄다고 의심하기 시작하는 시점 |
| 저절로 움직이는 것 5초 넘으면 멈출 수 있게, 깜빡임 1초에 3번 미만, 소리 3초 | 10-2 | 웹 접근성 국제 기준 |
| 나란한 선택지 2개 | 4-1 | 한눈에 비교할 수 있는 수 |
| 라디오 2~5개 | 8-2 | 펼쳐 둔 채 비교할 수 있는 수 |
| 원하는 기능까지 이동 3번 이내 | 3-4 | 길을 잃지 않는 깊이 |
| 확인 요청 선택지 2개 | 6-1 | 반드시 골라야 하는 순간의 부담을 줄이는 수 |

## 1. 핵심 원칙

규칙에 없는 상황에서는 이 8가지로 판단합니다.

| 원칙 | 한 줄 설명 | 사용자가 느껴야 하는 것 |
| --- | --- | --- |
| 명확성 | 지금 무엇을 할 수 있는지 바로 보인다 | "여기서 뭘 하면 되는지 알겠다" |
| 일관성 | 같은 일은 언제나 같은 방식으로 한다 | "전에 해 본 대로 하면 되겠다" |
| 피드백 | 모든 행동에 즉시 반응한다 | "눌렸구나, 처리되고 있구나" |
| 오류 예방 | 실수할 기회를 줄인다 | "실수할 일이 별로 없다" |
| 통제권 | 언제든 취소하고 되돌릴 수 있다 | "잘못해도 되돌릴 수 있다" |
| 인지 부담 최소화 | 기억하지 않고 보고 고르게 한다 | "생각할 게 많지 않다" |
| 포용성 | 누구나, 어떤 기기·설정에서도 쓸 수 있다 | "나도 쓸 수 있다" |
| 신뢰 | 숨기는 것 없이 미리 알려 준다 | "믿고 진행해도 되겠다" |

## 2. 정보 구조

- **[필수]** 한 화면은 하나의 목적만 가진다. 목적을 한 문장으로 말할 수 없으면 화면을 나눈다.
- **[필수]** 화면 제목만 보고 이 화면에서 무엇을 하는지 알 수 있다.
- **[필수]** 가장 중요한 정보와 행동을 먼저, 위에 둔다.
- **[필수]** 결정에 필요한 정보는 결정하는 곳 바로 근처에 둔다. 다른 화면에서 기억해 오게 하지 않는다.
- **[필수]** 처음부터 모든 옵션을 보여 주지 않는다. 고급 옵션은 펼치거나 다음 단계로 넘긴다.
- **[권장]** 긴 과정은 단계로 나누고, 지금 몇 번째 단계인지와 남은 단계를 보여 준다.
- **[권장]** 비슷한 항목은 같은 순서·형식으로 나열해 훑어보고 비교하기 쉽게 한다.
- **[권장]** 같은 대상을 만드는 화면과 고치는 화면은 같은 구성으로 만든다.

## 3. 이동

### 3-1. 현재 위치

- **[필수]** 사용자는 언제나 지금 어느 화면에 있는지 알 수 있다.
- **[필수]** 지금 선택된 탭이나 메뉴가 무엇인지 분명히 보여 준다.

### 3-2. 뒤로가기와 닫기는 다르다

| 구분 | 뒤로가기 | 닫기 |
| --- | --- | --- |
| 하는 일 | 이전 화면으로 한 단계 돌아감 | 지금 열린 층(시트, 전체 화면 팝업)이나 과정을 끝냄 |
| 쓰는 곳 | 일반 화면, 단계가 이어지는 화면 | 위로 덮어 연 화면, 독립된 과정 |
| 입력 내용 | 유지된다 | 사라질 수 있다 → 7-3 규칙 적용 |

- **[필수]** 화면이 쌓여 들어온 곳에는 뒤로가기, 위로 덮어 연 곳에는 닫기를 쓴다. 둘을 섞지 않는다.
- **[필수]** 기기의 뒤로가기(안드로이드 버튼, 아이폰 가장자리 밀기)는 화면 안의 뒤로가기·닫기와 똑같이 동작한다. (웹 프로토타입에서 확인 불가)
- **[필수]** 뒤로가기로 돌아갈 곳은 흐름 성격에 따라 정한다.
  - 검색·추천처럼 둘러보는 흐름: **지나온 순서대로** 돌아간다.
  - 설정·프로필처럼 구조가 고정된 흐름: **앱 구조상 한 단계 위**로 돌아간다.
  - 외부 링크로 상세 화면에 바로 들어온 경우: 앱 밖으로 나가지 않고 앱 구조상 위 화면으로 간다.

### 3-3. 돌아왔을 때

- **[필수]** 이전 화면은 떠날 때 모습 그대로다. 스크롤 위치, 선택한 탭, 검색어, 필터를 유지한다.

### 3-4. 흐름

- **[필수]** 막다른 화면을 만들지 않는다. 모든 화면에 다음 행동이나 돌아갈 길이 있다.
- **[필수]** 완료 화면에서 뒤로가기로 이미 끝난 과정(결제, 송금)에 다시 들어가지 않게 한다.
- **[필수]** 같은 화면 안에서 내용 묶음만 바꾸는 탭과, 다른 화면으로 가는 이동을 구분한다.

  | 구분 | 탭 | 다른 화면으로 이동 |
  | --- | --- | --- |
  | 화면 제목·위쪽 영역 | 그대로 | 새 화면의 제목으로 바뀜 |
  | 바뀌는 곳 | 탭 아래 내용만 | 화면 전체 |
  | 움직임 | 내용만 바뀜 (화면 전환 움직임 없음) | 화면 전환 움직임 (10-1) |
  | 뒤로가기 | 탭을 바꿔도 기록이 쌓이지 않음. 뒤로가기는 이전 화면으로 | 이동한 화면에 뒤로가기가 생김 |
  | 생김새 | 선택된 탭 표시가 있는 탭 묶음 | 목록 한 줄, 화살표(›), 버튼 |
- **[권장]** 원하는 기능까지 3번 이내로 이동할 수 있게 한다.

## 4. 인터랙션

### 4-1. 행동의 위계

- **[필수]** 한 화면의 주요 행동은 1개다.
- **[필수]** 주요 행동과 보조 행동은 강조 정도로 구분된다.
- **[권장]** 나란히 놓는 선택지는 2개까지. 3개 이상이면 목록으로 모아 고르게 한다.
- **[권장]** 화면 위쪽 보조 행동이 많으면 중요한 것만 보이고 나머지는 '더보기'에 모은다. 더보기 목록은 Bottom sheet로 만들며, 구성은 `PATTERNS.md`를 따른다.

### 4-2. 예측 가능성

- **[필수]** 누르기 전에 결과를 예상할 수 있다. 버튼은 결과를 말하고, 누르면 그 결과가 일어난다.
- **[필수]** 누를 수 있는 것은 누를 수 있어 보이고, 누를 수 없는 것은 그렇게 보이지 않는다.
- **[필수]** 누를 수 있어 보이는 영역 전체가 눌린다. 체크·라디오·스위치는 옆 글자를, 목록 한 줄에 들어 있으면 그 줄 전체를 눌러도 동작한다.
- **[필수]** 같은 모양의 요소는 어느 화면에서든 같은 동작을 한다.

### 4-3. 손가락으로 쓰기 쉽게

- **[필수]** 누를 수 있는 영역은 44×44px 이상을 기본으로 한다. 아이콘처럼 보이는 크기가 작아도 누르는 영역은 이 크기를 확보한다. (크기 값 자체는 `DESIGN.md`가 이 기준을 만족하도록 정한다)
  - 44px은 손가락 오조작을 줄이기 위한 **엄격한 기준**이다. 공간이 부족한 경우(촘촘한 목록 안의 보조 아이콘, 문장 속 링크, 입력칸 안의 지우기 버튼 등)에는 그보다 작은 영역도 쓸 수 있다. 단, **최소 24×24px**는 반드시 확보하고, 주변의 누를 수 있는 요소와 충분히 떨어뜨려 옆을 잘못 누르지 않게 한다.
- **[필수]** 누를 수 있는 요소끼리 붙어 있어 옆을 잘못 누르는 일이 없게 한다.
- **[권장]** 자주 누르는 행동은 한 손 엄지가 닿기 쉬운 화면 아래쪽에 둔다.

### 4-4. 제스처

- **[필수]** 밀기·끌기·길게 누르기·두 손가락 동작으로만 할 수 있는 기능을 만들지 않는다. 보이는 버튼으로도 할 수 있어야 한다.
- **[필수]** 화면 확대를 막지 않는다.

### 4-5. 중복 실행 방지

- **[필수]** 처리 중인 행동은 다시 실행되지 않는다. 결제·전송·저장은 끝날 때까지 다시 누를 수 없다.
- **[권장]** 버튼을 막는 것만으로는 부족하다. 연결이 끊겼다 다시 보내지거나 빠르게 두 번 눌려 **같은 요청이 서버에 두 번 가도 결과는 한 번만 일어나게** 한다 (멱등성). 결제·송금·주문은 요청마다 같은 요청임을 알아볼 수 있는 표시를 함께 보낸다.

### 4-6. 눌림 반응

- **[필수]** 누르는 순간 반응한다. 반응이 없으면 사용자는 다시 누른다.
- **[필수]** 기본 반응은 **색 변화**다. 기기의 '동작 줄이기' 설정과 상관없이 항상 보이기 때문이다.
- **[권장]** 하나의 면으로 보이는 요소(버튼, 카드, 목록 한 줄)는 살짝 작아지는 반응을 더한다. 색 변화와 같은 순간에 시작하고 끝난다.
- **[필수]** 작아지는 반응을 쓰지 않는 경우:

  | 경우 | 이유 |
  | --- | --- |
  | 문장 안의 링크 글자 | 영역이 한 면으로 잡히지 않아 무엇이 눌렸는지 안 보인다 |
  | 안에 서로 대등한 동작이 여럿인 요소 (열기·좋아요·저장이 나란한 카드) | 전체가 줄면 무엇을 눌렀는지 모호하다. 누른 대상만 반응한다 |
  | 이미 작아지는 요소 안에 들어 있는 요소 | 두 번 겹쳐 과하게 줄어든다. 바깥 요소만 반응한다 |
  | 로딩·비활성 상태 | 입력을 받지 않는 상태다 |
  | '동작 줄이기' 설정이 켜진 경우 | 색 변화만 남긴다 |

- **[필수]** 눌려서 작아져도 주변 요소의 자리는 움직이지 않는다.

## 5. 상태

### 5-1. 요소의 상태

누를 수 있는 모든 요소는 아래 상태를 가집니다. 각 상태의 모양은 `DESIGN.md`가 정합니다.

| 상태 | 언제 | 반응 규칙 |
| --- | --- | --- |
| 기본 | 아무 조작이 없을 때 | — |
| 눌림 | 누르고 있는 동안 | 4-6 |
| 선택됨 | 켜짐·선택됨 | 눌림과 함께 올 수 있다. 눌려도 선택 표시는 유지된다 |
| 비활성 | 지금은 쓸 수 없음 | 눌림 반응 없음. 다른 상태와 겹치지 않는다 |
| 로딩 | 처리 중 | 눌림 반응 없음. 추가 입력을 받지 않는다 |

- **[필수]** 선택됨은 색만으로 구분하지 않는다. 체크 표시·굵기 같은 모양 차이를 함께 둔다.
- **[필수]** 비활성일 때는 왜 쓸 수 없는지, 무엇을 하면 쓸 수 있는지 근처에서 알 수 있게 한다.
- **[권장]** 비활성인 항목은 이름 글자까지 함께 비활성으로 보여, 일부만 꺼진 것으로 오해하지 않게 한다.
- **[필수]** 로딩 중인 버튼은 버튼 이름을 그대로 두고 처리 중 표시만 더한다.

### 5-2. 화면의 상태

- **[필수]** 데이터를 보여 주는 화면은 아래 상태를 모두 설계한다. 정상 상태만 만들지 않는다.

| 상태 | 언제 | 사용자에게 줘야 할 것 |
| --- | --- | --- |
| 로딩 | 불러오는 중 | 무언가 오고 있다는 신호 (5-3) |
| 정상 | 데이터가 있음 | 내용 |
| 처음·빈 상태 | 아직 아무것도 없음 | 왜 비었는지 + 채우는 첫 행동 |
| 결과 없음 | 검색·필터 조건에 맞는 것이 없음 | 조건을 바꾸거나 초기화하는 방법 |
| 오류 | 불러오기 실패 | 무엇이 잘못됐는지 + 다시 시도 |
| 연결 끊김 | 인터넷이 안 됨 | 연결 상태 안내 + 다시 시도 |
| 권한 없음 | 볼 수 없는 내용 | 이유 + 권한을 얻는 방법 또는 돌아갈 길 |
| 완료 | 과정을 마침 | 결과 + 다음 행동 |

- **[필수]** 빈 상태와 오류 상태는 다르게 보여 준다. 오류인데 "내용이 없어요"로 보이면 안 된다.
- **[필수]** 실패 화면의 나가는 방법은 상황에 맞게 고른다.

  | 상황 | 제공할 행동 |
  | --- | --- |
  | 입력이 잘못돼 고쳐야 함 | 뒤로가기 (직전 단계로) |
  | 덮어 연 화면에서 실패 | 닫기 (원래 보던 화면으로) |
  | 되돌아갈 곳이 없음 | 홈 등 안전한 곳으로 가는 버튼 |
  | 같은 작업을 다시 하면 될 수 있음 | 다시 시도 (위 행동과 함께) |

- **[필수]** 내용이 1개일 때, 보통일 때, 아주 많을 때 모두 화면이 깨지지 않는다.
- **[필수]** 이름·제목·주소처럼 사용자가 입력한 글은 아주 짧거나 아주 길어도 화면이 깨지지 않는다.

### 5-3. 로딩

#### 걸리는 시간에 따라

| 걸리는 시간 | 사용자 경험 | 해야 할 일 |
| --- | --- | --- |
| 1초 이내 | 바로 된 것처럼 느낌 | 로딩 표시를 하지 않는다. 깜빡임만 생긴다 |
| 1~4초 | 잠깐 기다림 | 처리 중 표시 또는 콘텐츠 자리 미리 보여 주기 |
| 4~10초 | 지루함을 느끼기 시작 | 위에 더해, 진행 중이라는 안내 문장을 보여 준다 |
| 10초 이상 | 멈췄는지 의심함 | 진행 정도나 예상 시간을 보여 준다 |
| 1분 이상 | 다른 일을 하고 싶음 | 진행 정도 + 취소 + 다른 일을 하며 기다릴 수 있는 방법 |

#### 걸리는 시간을 미리 알 수 있는지에 따라

위 표는 **걸리는 시간을 미리 알 때** 기준입니다. 같은 요청이라도 네트워크에 따라 빠르기도 느리기도 하면 아래를 따릅니다.

| 경우 | 예 | 해야 할 일 |
| --- | --- | --- |
| 항상 1초 안에 끝남 | 화면 안 필터 바꾸기, 기기에 저장된 값 불러오기 | 로딩 표시를 하지 않는다 |
| 시간을 미리 알 수 없음 | 서버에서 목록 불러오기, 저장·제출 | 바로 보여 주지 않고 **조금 기다렸다가** 그때도 안 끝났으면 보여 준다. 한 번 보이면 **잠깐은 유지**한다. 빠른 응답에서 표시가 번쩍이지 않게 하기 위해서다 (지연·유지 시간 값은 `DESIGN.md`) |
| 진행 정도를 알 수 있는 긴 작업 | 파일 올리기, 큰 내려받기 | 처음부터 진행 정도를 보여 준다 |

#### 상황에 따라

| 상황 | 로딩 표현 |
| --- | --- |
| 목록·카드처럼 모양이 정해진 화면을 처음 불러올 때 | 콘텐츠 자리를 미리 보여 주기 |
| 버튼을 눌러 저장·제출할 때 | 그 버튼 안에서 처리 중 표시 |
| 스크롤해 더 불러올 때 | 목록 끝에 작은 처리 중 표시 |
| 당겨서 새로고침할 때 | 당긴 자리에 처리 중 표시 |
| 메시지 전송처럼 일부만 처리할 때 | 그 항목 옆에만 처리 중 표시 |

- **[필수]** 화면 전체를 가리는 로딩은 마지막 수단이다. 처리 중인 부분에만 표시한다.
- **[필수]** 로딩 중에도 이미 아는 정보(화면 제목, 전에 받은 데이터)는 먼저 보여 준다.
- **[필수]** 로딩이 끝날 때 요소가 갑자기 밀리거나 튀지 않게 한다. 콘텐츠 자리 미리 보여 주기는 실제 콘텐츠와 같은 모양으로 만든다.
- **[필수]** 한 영역에 로딩 표현을 두 가지 겹쳐 쓰지 않는다.
- **[필수]** 로딩이 실패로 끝나면 오류 상태(5-2)로, 성공으로 끝나면 결과를 보여 준다. 간단한 불러오기는 성공 메시지가 필요 없다.
- **[필수]** 진행 정도를 알 수 없는 요청이 **10초** 안에 끝나지 않으면, 계속 돌게 두지 말고 오류 상태(5-2)로 바꿔 **다시 시도**를 준다. 진행 정도를 보여 주는 긴 작업(파일 올리기 등)은 제외한다.
- **[권장]** 성공 가능성이 높은 행동(좋아요, 저장)은 결과를 먼저 화면에 반영하고, 실패하면 되돌리고 알린다.
- **[필수]** 처리 중 표시는 **Spinner**, 콘텐츠 자리 미리 보여 주기는 **Skeleton** 컴포넌트로 만든다.

## 6. 피드백

### 6-1. 피드백의 종류

어떤 종류를 쓸지는 아래로 정하고, 각 종류를 어떤 컴포넌트로 보여 줄지는 `DESIGN.md`를 따릅니다.

| 종류 | 언제 | 사용자 행동 | 닫히는 방법 |
| --- | --- | --- | --- |
| 일시 알림 | 방금 한 행동의 결과 (저장됨, 복사됨) | 아무것도 안 해도 됨 | 잠시 뒤 저절로 |
| 확인 요청 | 되돌릴 수 없는 행동 직전, 반드시 알아야 할 안내 | 반드시 골라야 넘어감 | 버튼을 눌러야만 |
| 선택 목록 | 여러 행동이나 옵션 중 고르기 | 고르거나 닫음 | 고르기, 닫기, 바깥 누르기 |
| 제자리 메시지 | 특정 입력·영역에 대한 안내·오류 | 그 자리에서 고침 | 문제가 해결되면 |
| 지속 안내 | 해결될 때까지 알아야 할 상태 | 필요하면 조치 | 상태가 바뀌면 |

- 제자리 메시지는 Input·Textarea·Select의 오류·도움말로 보여 준다. 따로 부품을 만들지 않는다.
- 지속 안내는 **Banner** 컴포넌트로 보여 준다.

- **[필수]** 결정이 필요한 내용을 일시 알림으로 보여 주지 않는다. 사라지면 놓친다.
- **[필수]** 단순 결과를 확인 요청으로 보여 주지 않는다. 흐름을 끊는다.
- **[필수]** 확인 요청의 선택지는 2개 이하다. 3개 이상이면 선택 목록을 쓴다.
- **[필수]** 확인 요청은 바깥을 눌러 닫히지 않는다. 반드시 버튼으로 고르게 한다.

### 6-2. 일시 알림

- **[필수]** 한 번에 하나만 보여 준다. 새 알림은 앞의 것이 사라진 뒤 차례로 나온다.
- **[필수]** 읽을 수 있을 만큼 충분히 보여 주고, 손을 대고 있는 동안은 사라지지 않는다. 보여 주는 시간 값은 `DESIGN.md`가 정한다.
- **[필수]** 행동 버튼은 최대 1개이고, "확인" 대신 "되돌리기", "보러가기"처럼 구체적인 행동을 말한다.
- **[필수]** 화면 아래 고정된 버튼이나 다른 행동을 가리지 않는다.

## 7. 오류 예방과 복구

### 7-1. 예방이 먼저

- **[필수]** 오류 메시지를 잘 쓰기보다 오류가 일어나지 않게 하는 것이 먼저다.
- **[필수]** 고를 수 있는 값은 직접 입력하게 하지 않고 선택지로 준다.
- **[권장]** 잘못된 값을 미리 막을 때는 막는 이유를 함께 알려 준다 (예: 지난 날짜는 고를 수 없음 + 안내).

### 7-2. 위험한 행동

| 행동 유형 | 예 | 처리 방법 |
| --- | --- | --- |
| 되돌릴 수 있음 | 목록에서 지우기, 보관하기 | 바로 실행 + 되돌리기 제공 |
| 되돌릴 수 없음 | 영구 삭제, 탈퇴, 결제, 송금, 설정 초기화 | 실행 전 확인 요청 |
| 되돌릴 수 없고 영향이 큼 | 계정 삭제, 큰 금액 송금 | 확인 요청 + 무엇이 사라지는지 구체적으로 안내 |

- **[필수]** 확인 요청의 실행 선택지는 행동을 그대로 말한다 ("삭제하기", "송금하기"). 위험한 쪽은 실행 버튼이며, 취소 버튼을 위험하게 보이게 하지 않는다.
- **[필수]** 확인 요청은 되돌릴 수 없는 행동에만 쓴다. 자주 띄우면 읽지 않고 누르게 된다.

### 7-3. 작성 중인 내용 보호

- **[필수]** 입력한 내용이 있는 화면을 떠나려 하면, 내용이 사라진다는 것을 알리고 확인받는다.
- **[필수]** 바뀐 내용이 없거나 자동 저장이 되는 화면은 확인 없이 떠날 수 있다.
- **[권장]** 긴 입력은 자동으로 임시 저장한다.

### 7-4. 오류가 났을 때

- **[필수]** 오류 메시지는 무슨 일인지, 왜인지(알 수 있으면), 어떻게 하면 되는지를 담는다.
- **[필수]** 오류는 문제가 생긴 자리 근처에 보여 준다.
- **[필수]** 오류가 나도 사용자가 입력한 내용은 지우지 않는다.
- **[필수]** 시스템 오류 코드나 기술 용어를 그대로 보여 주지 않는다. 사용자 탓으로 느껴지게 말하지 않는다 (표현은 `WRITING.md`).

## 8. 폼

### 8-1. 구성

| 단위 | 뜻 |
| --- | --- |
| 입력칸 | 실제로 값을 넣는 곳 |
| 항목 | 이름(라벨) + 입력칸 + 도움말·오류 |
| 묶음 | 관련 있는 항목 여러 개 |
| 폼 | 항목 전체를 검사하고 제출하는 단위 |

- **[필수]** 꼭 필요한 것만 묻는다. 이미 아는 정보는 다시 묻지 않고 미리 채운다.
- **[필수]** 항목 순서는 사용자가 생각하는 순서를 따른다 (이름 → 연락처 → 주소).
- **[권장]** 관련 항목은 묶고, 한 화면이 복잡해지면 단계로 나눈다.

### 8-2. 어떤 입력 방식을 쓸지

| 사용자가 하는 일 | 입력 방식 |
| --- | --- |
| 자유롭게 짧은 글 쓰기 | 한 줄 입력 |
| 자유롭게 긴 글 쓰기 | 여러 줄 입력 |
| 2~5개 중 **하나** 고르기, 차이를 비교해야 함 | 라디오 (세로로 나열) |
| 6개 이상 중 하나 고르기, 또는 개수가 늘어날 수 있음 | 선택 목록 (평소엔 고른 값만 보임) |
| 여러 개 고르기, 동의 | 체크박스 |
| 켜는 **즉시** 적용되는 설정 | 스위치 |
| 켜고 나서 **저장해야** 적용되는 선택 | 체크박스 |

- **[필수]** 하나만 고르는 곳에 체크박스를, 여러 개 고르는 곳에 라디오를 쓰지 않는다.
- **[필수]** 저장 버튼을 눌러야 적용되는 곳에 스위치를 쓰지 않는다.
- **[필수]** "전체 선택"이 필요하면 스위치가 아니라 상위 체크박스로 하위 항목을 함께 고르게 한다. 하위 일부만 고르면 상위는 '일부 선택' 상태로 보인다.
- **[필수]** 라디오는 세로로 나열한다. 가로로 두면 어떤 글자가 어떤 버튼인지 헷갈린다.
- **[권장]** 라디오와 선택 목록은 가장 많이 고르는 값을 기본으로 골라 둔다. 단, 동의·결제·유료 옵션은 미리 고르지 않는다.
- **[필수]** 선택 목록에서 "없음"도 답이 될 수 있으면 "없음" 옵션을 목록에 둔다. 반드시 골라야 하는 항목은 고르지 않으면 제출되지 않게 한다.
- **[필수]** 여러 개 고르는 목록에 최대 개수가 있으면 미리 알려 준다 ("최대 3개").

### 8-3. 항목 이름과 안내

- **[필수]** 모든 항목에는 항상 보이는 이름이 있다. 입력칸 안 흐린 안내 글자를 이름 대신 쓰지 않는다. 입력하거나 고르면 사라지기 때문이다.
- **[필수]** 안내 글자는 입력 예시를 보여 줄 때만 쓴다 (010-1234-5678).
- **[필수]** 비밀번호처럼 조건이 있으면 조건을 입력 전에 보여 준다.
- **[필수]** 필수·선택 표시는 한 폼 안에서 한 가지 방식만 쓴다.
  - 항목의 2/3 이상이 필수 → 선택 항목에만 "(선택)"
  - 그 외 → 필수 항목에만 필수 표시
- **[필수]** 도움말과 오류가 동시에 있으면 오류만 보여 준다. 같은 자리에 두 문장이 겹치면 무엇을 해야 하는지 흐려진다. 오류가 사라지면 도움말을 다시 보여 준다.

### 8-4. 입력을 쉽게

- **[필수]** 입력 종류에 맞는 키보드를 띄운다. (웹 프로토타입에서 확인 불가)

  | 입력 | 키보드 |
  | --- | --- |
  | 숫자, 금액, 인증번호 | 숫자 키패드 |
  | 전화번호 | 전화 키패드 |
  | 이메일 | 이메일 키보드 |
  | 검색 | 검색 버튼이 있는 키보드 |

- **[필수]** 붙여넣기를 막지 않는다. 인증번호·계좌번호도 붙여넣을 수 있다.
- **[필수]** 기기의 자동 완성(이름, 주소, 문자로 온 인증번호)이 동작하게 한다. (웹 프로토타입에서 확인 불가)
- **[필수]** 하이픈·띄어쓰기 형식을 사용자가 맞추게 하지 않는다. 어떻게 입력하든 자동으로 맞춘다.
- **[필수]** 앞뒤 공백 때문에 오류가 나지 않게 한다.
- **[필수]** 다른 글자를 아예 못 넣게 막지 않는다. 입력은 받고 안내한다.
- **[필수]** 키보드가 올라와도 입력 중인 칸과 제출 버튼이 가려지지 않는다.
- **[권장]** 한 칸을 마치면 다음 칸으로 자연스럽게 넘어간다.
- **[권장]** 입력칸이 하나뿐인 화면(검색, 인증번호)만 들어오자마자 키보드를 띄운다. 그 외 화면은 사용자가 칸을 누를 때 띄운다. 들어오자마자 키보드가 올라오면 보이는 영역이 갑자기 줄어 화면이 흔들리고, 키보드가 내용을 가린다.

### 8-5. 검사

| 방식 | 언제 검사 | 쓰는 곳 |
| --- | --- | --- |
| 제출 시 검사 | 제출 버튼을 눌렀을 때 전체 | 기본. 서버 규칙·업무 규칙 확인 |
| 제자리 검사 | 칸을 벗어날 때 그 칸만 | 필수 여부·글자 수 같은 단순 규칙, 항목이 많은 폼, 금융·보안 정보처럼 잘못 넣으면 위험한 칸 |

- **[필수]** 입력하는 도중에는 오류를 보여 주지 않는다. 다 쓰기도 전에 혼나는 느낌을 준다.
- **[필수]** 한 번 오류가 난 칸은 다시 입력할 때마다 검사해, 고치는 즉시 오류가 사라진다.
- **[필수]** 오류는 해당 칸 바로 근처에 문장으로 보여 준다. 색만으로 알리지 않는다. 화면 위에 모아서 보여 주지 않는다.
- **[필수]** 제출 시 오류가 있으면 첫 번째 오류 칸으로 이동한다.

### 8-6. 제출

- **[필수]** 제출 버튼은 결과를 말한다 ("가입하기", "주문하기").
- **[필수]** 제출 후 처리 중에는 다시 누를 수 없다.
- **[필수]** 다 채우기 전에는 제출 버튼을 누를 수 없게 하고(B안), 누를 수 없는 이유를 사용자가 알 수 있게 한다 (5-1).

  검토한 안:

  | 안 | 방식 | 장점 | 단점 |
  | --- | --- | --- | --- |
  | A | 항상 누를 수 있고, 누르면 빠진 항목을 알려 줌 | 무엇이 빠졌는지 바로 앎 | 빈 폼에서 오류가 한꺼번에 뜰 수 있음 |
  | B | 다 채울 때까지 누를 수 없음 | 국내 앱 사용자에게 익숙함 | 왜 안 눌리는지 모를 수 있음 |

  판단 근거:

  | 관점 | 입장 |
  | --- | --- |
  | 웹 인터페이스 가이드 | A안. 제출 버튼을 미리 비활성화하지 말고, 제출하게 한 뒤 검사 결과를 보여 준다 |
  | 모바일 디자인 시스템 | 둘 다 허용 |
  | 국내 앱 관행 | B안이 많음 |

## 9. 레이아웃·반응형

값(여백, 폭, 그리드)은 `DESIGN.md`가 정하고, 여기서는 **화면이 바뀌어도 사용자가 잃지 않아야 할 것**을 정합니다.

### 9-1. 가려지면 안 되는 것

화면 가장자리는 상태 표시줄, 홈 표시줄, 카메라 구멍, 둥근 모서리에 가려질 수 있습니다. 이 영역을 피한 곳을 **안전 영역**이라고 합니다.

| 요소 | 배치 | 이유 |
| --- | --- | --- |
| 누를 수 있는 것 (버튼, 입력칸, 탭) | 안전 영역 안 | 가려지면 누를 수 없다 |
| 읽어야 하는 것 (글, 가격, 의미 있는 아이콘·이미지) | 안전 영역 안 | 가려지면 정보를 잃는다 |
| 배경, 구분선, 꾸미기 이미지 | 화면 끝까지 | 가려져도 잃는 것이 없고, 중간에 끊기면 어색하다 |
| 스크롤되는 목록, 가로 스크롤 탭 | 화면 끝까지 | 스크롤하면 다시 보이므로 잃지 않는다 |
| 화면에 고정된 버튼·바 | 안전 영역 안 | 스크롤로 가져올 수 없다 |

- **[필수]** 여백은 화면 끝이 아니라 안전 영역 경계부터 잰다. (웹 프로토타입에서 확인 불가)
- **[필수]** 가운데 정렬은 안전 영역의 가운데를 기준으로 한다. (웹 프로토타입에서 확인 불가)
- **[필수]** 안전 영역 크기는 기기·화면 방향·화면 분할에 따라 달라진다. 특정 기기 값을 고정해 쓰지 않는다. (웹 프로토타입에서 확인 불가)

### 9-2. 화면 크기와 방향

- **[필수]** 기준 폭보다 좁은 화면(작은 폰)에서도 글자가 잘리거나 겹치지 않는다. 길면 줄바꿈한다.
- **[필수]** 기준 폭보다 넓은 화면(큰 폰, 태블릿)에서 콘텐츠를 무작정 늘리지 않는다. 읽기 좋은 폭을 유지하고 가운데 둔다. (최대 폭 값은 `DESIGN.md`)
- **[필수]** 화면이 회전하거나 분할돼도 입력한 내용과 스크롤 위치를 잃지 않는다.
- **[권장]** 가장 작은 화면부터 설계하고, 넓어지면 확장한다.

### 9-3. 글자 크기와 콘텐츠 길이

- **[필수]** 기기의 글자 크기 설정을 키워도 잘리거나 겹치지 않는다. 높이가 고정된 상자에 글자를 가두지 않는다.
- **[필수]** 버튼 이름이 길어지거나 글자가 커져서 나란한 버튼에 다 들어가지 않으면, 세로로 쌓는 등 배치를 바꾼다.
- **[필수]** 한 줄로만 보여야 하는 곳(화면 제목, 고른 값 표시)은 넘치면 말줄임으로 자르고, 잘린 내용은 다른 곳에서 볼 수 있게 한다.

### 9-4. 키보드

- **[필수]** 키보드가 올라오면 보이는 영역이 줄어든다는 것을 전제로 설계한다. 입력 중인 칸과 다음 행동이 보이는 곳에 있어야 한다.
- **[필수]** 화면 아래에서 올라온 층(시트) 안에서 입력할 때도 키보드가 입력칸을 가리지 않는다.

### 9-5. 고정 영역과 스크롤

- **[권장]** 화면 위쪽 제목 영역은 스크롤해도 고정된다.
- **[필수]** 아래에 고정된 버튼이 본문 마지막 내용을 가리지 않는다.
- **[권장]** 스크롤 영역 안에 같은 방향의 스크롤 영역을 또 만들지 않는다.
- **[권장]** 내용이 더 있으면 더 있다는 것을 알 수 있게 한다 (아래쪽이 잘려 보이게 두기 등).

## 10. 모션

시간·속도 곡선 값은 `DESIGN.md`가 정합니다.

### 10-1. 종류

| 종류 | 예 | 목적 |
| --- | --- | --- |
| 작은 움직임 | 눌림, 입력칸 선택, 스위치 켜기 | 입력이 전달됐음을 알림 |
| 큰 움직임 | 화면 전환, 시트·팝업 열고 닫기 | 어디서 와서 어디로 갔는지 알림 |

- **[필수]** 같은 종류의 움직임은 앱 전체에서 같은 방식으로 움직인다. 나타날 때와 사라질 때를 구분한다.
- **[필수]** 움직임은 원인과 결과를 이해시킬 때만 쓴다. 꾸미기용 움직임은 쓰지 않는다.
- **[필수]** 시트는 아래에서 올라오고 아래로 내려간다. 들어온 방향으로 나간다.

### 10-2. 사용자를 방해하지 않기

- **[필수]** 움직이는 중에도 누르면 바로 반응한다. 끝날 때까지 기다리게 하지 않는다.
- **[필수]** '동작 줄이기' 설정이 켜져 있으면 크기·위치가 바뀌는 움직임을 끄고, 색 변화·나타나기만 남긴다.
- **[필수]** 저절로 5초 넘게 이어지는 움직임(자동으로 넘어가는 배너, 반복되는 애니메이션)은 멈추거나 건너뛸 수 있게 한다.
- **[필수]** 1초에 3번 이상 깜빡이지 않는다. 광과민성 발작을 일으킬 수 있다.
- **[필수]** 소리·영상은 자동 재생하지 않는다. 필요하면 소리 없이 시작하고, 3초 넘는 소리에는 멈춤·음량 조절을 둔다.

## 11. 접근성

색 대비는 `DESIGN.md`의 기준(APCA 방식)을 따릅니다. 기준값(숫자)은 `DESIGN.md`에만 적고, 여기서는 어떤 글자·요소를 어느 단계로 볼지만 정합니다.

### 11-1. 보는 데 어려움이 있는 사용자

- **[필수]** 색만으로 의미를 전달하지 않는다. 성공·오류·선택에는 글자나 모양을 함께 쓴다.
- **[필수]** 글자는 역할에 맞는 대비 단계의 색으로 쓴다. 단계별 기준값과 어떤 색이 어느 단계를 만족하는지는 `DESIGN.md`가 정한다.

  | 글자 종류 | 예 | 대비 단계 (`DESIGN.md` 이름) |
  | --- | --- | --- |
  | 본문 | 설명 문장, 목록 내용, 사용자가 입력한 값 | 가독성 텍스트(본문) |
  | 보조 글자 | 항목 이름(라벨), 캡션, 날짜, 버튼 이름 | 다른 텍스트 |
  | 흐린 글자 | 입력칸 안 예시 글자, 비활성 글자 | placeholder·disabled 글자 |

- **[필수]** 흐린 글자에는 꼭 알아야 할 정보를 담지 않는다. 읽지 못해도 쓰는 데 지장이 없어야 한다. 항목 이름은 8-3, 비활성 이유는 5-1처럼 따로 보이는 글자로 알린다.
- **[필수]** 글자가 아닌 요소 중 의미가 있는 것(입력칸 테두리, 체크박스·라디오·스위치의 테두리, 의미 있는 아이콘, 포커스 표시)은 배경과 구분되게 보인다. 꾸미기 구분선·배경 장식은 해당하지 않는다. 기준값은 `DESIGN.md`가 정한다(14장).
- **[필수]** 아이콘만 있는 버튼에는 화면 낭독기가 읽을 이름을 붙인다 (뒤로가기 → "뒤로 가기").
- **[필수]** 의미 있는 이미지에는 짧은 설명을, 꾸미기 이미지는 화면 낭독기가 건너뛰게 한다.
- **[필수]** 화면 낭독기가 읽는 순서는 눈으로 보는 순서와 같다.
- **[필수]** 새로 나타나는 알림·오류는 화면 낭독기가 읽어 준다. 급하지 않은 알림은 읽던 내용을 마친 뒤 읽는다.
- **[필수]** 화면 낭독기로 모든 기능을 쓸 수 있다.

### 11-2. 몸을 움직이는 데 어려움이 있는 사용자

- **[필수]** 모든 기능을 한 번 누르기로 쓸 수 있다 (4-4).
- **[필수]** 누르는 영역이 충분히 크다 (4-3).
- **[필수]** 시간 제한이 있는 화면(인증번호 입력)은 남은 시간을 보여 주고 연장할 수 있게 한다.

### 11-3. 이해하는 데 어려움이 있는 사용자

- **[권장]** 한 화면에서 한 번에 하나만 결정하게 한다.
- **[필수]** 같은 대상은 앱 전체에서 같은 이름으로 부른다.
- **[필수]** 숫자·날짜·시간·금액은 한국 사용자에게 익숙한 형식으로, 앱 전체에서 같게 보여 준다 (형식은 `WRITING.md`).

### 11-4. 개인 설정 존중

- **[필수]** 기기의 글자 크기, 동작 줄이기, 확대 설정을 따른다. 앱이 이 설정을 덮어쓰지 않는다.

## 12. 의사결정과 신뢰

- **[권장]** 한 번에 보여 주는 선택지는 적을수록 좋다. 많으면 묶거나 추천 항목을 위에 둔다.
- **[필수]** 비교할 선택지는 같은 기준·순서로 보여 준다.
- **[필수]** 돈이 오가기 전에 최종 금액, 수수료, 받는 사람(또는 상품), 결제 수단을 한 화면에서 확인하게 한다.
- **[필수]** 비용·조건·해지 방법을 숨기거나 작게 두지 않는다.
- **[필수]** 사용자에게 불리한 선택을 유도하지 않는다 (거절 버튼 숨기기, 유료 옵션 미리 선택, 가짜 긴급함).
- **[필수]** 기기 권한(위치, 카메라, 알림)은 그 기능을 쓰는 순간에, 이유를 먼저 알린 뒤 묻는다. 거절해도 나머지 기능은 쓸 수 있고, 다시 켜는 방법을 알려 준다.
- **[필수]** 비밀번호·계좌번호 같은 민감 정보는 가려서 보여 주고, 원할 때 볼 수 있게 한다.
- **[필수]** 사용자 동의 없이 결제·구독·공유가 일어나지 않는다.
- **[권장]** 긴 설명은 화면에 바로 보여 준다. 숨겨진 도움말(물음표 아이콘)은 마지막 수단이다.

## Do's and Don'ts

`/ui-review`가 이 목록을 그대로 점검표로 씁니다. "(웹 프로토타입에서 확인 불가)" 표시가 있는 항목은 점검을 건너뜁니다.

### 구조·이동

- [ ] 화면 목적을 한 문장으로 말할 수 있다
- [ ] 첫 화면이 아니면 뒤로가기 또는 닫기가 있고, 둘을 맞게 썼다
- [ ] 막다른 화면이 없고, 완료 화면에 다음 행동이 있다
- [ ] 다른 화면에 갔다 돌아와도 스크롤 위치·선택한 탭·검색어·필터가 그대로다
- [ ] 탭과 다른 화면으로의 이동이 구분된다

### 인터랙션

- [ ] 주요 행동이 1개다
- [ ] 버튼 이름만 보고 결과를 예상할 수 있다
- [ ] 누르는 영역이 44×44px 이상이고, 더 작다면 24×24px 이상이면서 주변 요소와 충분히 떨어져 있다
- [ ] 누르는 순간 색 변화로 반응하고, 작아지는 반응은 4-6의 제외 경우를 지킨다
- [ ] 제스처로만 할 수 있는 기능이 없다
- [ ] 처리 중인 행동을 다시 실행할 수 없다

### 상태·피드백

- [ ] 선택·비활성 상태가 색 외의 방법으로도 구분된다
- [ ] 로딩·빈·오류 상태가 설계되어 있고, 빈 상태와 오류가 구분된다
- [ ] 로딩 표현이 걸리는 시간과 상황에 맞고, 오래 걸리면 오류와 다시 시도로 넘어간다
- [ ] 내용이 1개·많을 때, 사용자 입력이 아주 짧거나 길 때도 화면이 깨지지 않는다
- [ ] 결정이 필요한 내용을 일시 알림으로 보여 주지 않는다

### 오류

- [ ] 되돌릴 수 없는 행동 앞에 확인 요청이 있다
- [ ] 작성 중 화면을 떠날 때 확인받는다
- [ ] 오류가 원인과 해결 방법을 담고, 문제 위치 근처에 있다

### 폼

- [ ] 모든 항목에 항상 보이는 이름이 있다
- [ ] 입력 방식이 8-2 표에 맞다 (특히 스위치·체크박스·라디오)
- [ ] 필수·선택 표시가 한 가지 방식이다
- [ ] 붙여넣기를 막지 않는다
- [ ] 입력 종류에 맞는 키보드가 뜨고, 자동 완성이 된다 (웹 프로토타입에서 확인 불가)
- [ ] 입력 도중에 오류를 보여 주지 않는다

### 레이아웃·반응형

- [ ] 누를 수 있는 것과 읽어야 하는 것이 안전 영역 안에 있다 (웹 프로토타입에서 확인 불가)
- [ ] 작은 화면과 큰 글자 설정에서 잘리거나 겹치지 않는다
- [ ] 키보드가 입력 중인 칸과 제출 버튼을 가리지 않는다
- [ ] 아래 고정 버튼이 본문 마지막 내용을 가리지 않는다

### 모션·접근성·신뢰

- [ ] 움직임이 원인과 결과를 설명하고, 동작 줄이기 설정을 따른다
- [ ] 저절로 5초 넘게 움직이는 것은 멈추거나 건너뛸 수 있다
- [ ] 아이콘만 있는 버튼에 읽을 이름이 있다
- [ ] 본문·보조·흐린 글자가 각자 맞는 대비 단계의 색을 쓴다
- [ ] 흐린 글자(예시 글자·비활성 글자)에 꼭 알아야 할 정보가 없다
- [ ] 입력칸 테두리·의미 있는 아이콘·포커스 표시가 배경과 구분된다
- [ ] 돈이 오가기 전에 최종 금액과 조건을 확인하는 화면이 있다
- [ ] 권한은 쓰는 순간에, 이유와 함께 묻는다
